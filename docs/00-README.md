# 📚 Nook — Documentation Pack

Welcome! This folder has **everything a developer needs** to build Nook, from
zero to a working product. Think of it like a box of LEGO instructions —
every document is one instruction booklet, and together they build the whole
set.

We wrote these documents so a **beginner developer** can read them and
understand *why* things are built the way they are, not just *what* to type.
Simple words, small steps, real examples.

## 🧭 Reading Order

Read the documents in this order — each one builds on the last:

| # | Document | What it tells you |
|---|----------|--------------------|
| 1 | `01-product-overview.md` | What Nook *is*, who it's for, and what we're building first |
| 2 | `02-tech-stack.md` | Which tools/languages we use, and why |
| 3 | `03-architecture.md` | How all the pieces (app, server, database) talk to each other |
| 4 | `04-database-schema.md` | How we store the data (tables, fields, relationships) |
| 5 | `05-api-specification.md` | Every "door" (endpoint) the frontend can knock on |
| 6 | `06-srs-requirements.md` | The full list of things the app must do (and must NOT do yet) |
| 7 | `07-developer-setup-guide.md` | How to install everything and run the project on your laptop |
| 8 | `08-roadmap-mvp.md` | The order we build features in, week by week |

## 🎯 One-sentence summary of Nook

> **Nook is a website where you save anything worth keeping — links, images,
> notes, videos — into folders called "Nooks", and you can share any Nook
> with a simple link like `nook.app/iftikhar/development`.**

## 🛠️ Who should read what

- **Frontend developer?** Read 1, 2, 3, 5, 7, 8.
- **Backend developer?** Read 1, 2, 3, 4, 5, 6, 7, 8.
- **Just want to set up the project and start coding?** Skip straight to
  `07-developer-setup-guide.md`, but come back and read the rest before
  writing real features — it will save you hours of confusion later.

## 🧒 A note on how these docs are written

Every document explains the *idea* in plain, simple language first (imagine
explaining it to a curious kid), and *then* gives the exact technical detail
(code, tables, JSON) right under it. Don't skip the simple explanation even
if you're experienced — it's there so nobody gets lost.
